HOW TO RUN — PulseETL
======================

A real weather intelligence pipeline. No API key needed. Runs entirely locally.


REQUIREMENTS
-------------
Python 3.9 or newer. Check with:
  python3 --version

That's the only prerequisite. Everything else is installed in Step 1.


STEP 1 — Install dependencies
-------------------------------
  pip install -r requirements.txt


STEP 2 — Initialize the database
----------------------------------
Creates the SQLite file and runs the schema (tables + views):
  python cli.py init-db


STEP 3 — Load historical data
-------------------------------
Pulls the last 30 days of weather for all configured cities:
  python cli.py backfill --days 30

This takes ~10–20 seconds. Safe to re-run — the pipeline is idempotent,
so no duplicate rows are ever created.


STEP 4 — Start the server
---------------------------
  python cli.py serve

This starts three things at once:
  - The FastAPI REST API    →  http://localhost:8000
  - The dashboard           →  http://localhost:8000/dashboard
  - The hourly scheduler    →  runs a fresh extract automatically every hour


Open http://localhost:8000/dashboard in your browser. That's it.


---


OPTIONAL COMMANDS
------------------

Run a single pipeline cycle manually (extract → transform → load):
  python cli.py run

Load more historical data:
  python cli.py backfill --days 60

Interactive API docs (auto-generated by FastAPI):
  http://localhost:8000/docs


API ENDPOINTS
--------------
  GET  /cities                        List all configured cities
  GET  /cities/{id}/readings          Latest weather readings for a city
  GET  /cities/{id}/trends            7-day rolling avg + day-over-day delta
  GET  /anomalies?days=30             Temperature anomalies (z-score > 2.5)
  GET  /runs?limit=20                 Pipeline run history and health
  POST /pipeline/run                  Trigger a manual pipeline run


RUNNING TESTS
--------------
  pytest tests/

Two test files:
  test_transform.py         — validates all rejection rules (null temp, future
                              timestamp, out-of-range values, deduplication)
  test_load_idempotency.py  — confirms re-running never duplicates rows,
                              values update correctly on re-load


CONFIGURING CITIES
-------------------
Edit config.py to add or remove cities. Each city needs:
  name, country, latitude, longitude, timezone

Then re-run:
  python cli.py init-db
  python cli.py backfill --days 30


DATABASE
---------
SQLite file is created at pulse.db (configurable via PULSE_DB env var).
It's a single file — open it with any SQLite browser
(e.g. DB Browser for SQLite, free at sqlitebrowser.org) to inspect
the schema and query the data directly.

Key tables:
  cities              — configured locations
  weather_readings    — all ingested hourly readings (unique per city+timestamp)
  rejected_records    — rows that failed validation, with reason
  pipeline_runs       — audit log of every E→T→L cycle

Key views (window functions):
  rolling_avg_temp    — 7-day rolling average per city
  daily_delta         — 24h temperature delta per city
  anomalies           — readings with z-score > 2.5 vs 30-day city mean
  city_latest         — most recent reading per city with temp rankings
